# Методы исправления проблем с установочным пакетом в AWS Lambda

Начните исследование и устранение ошибок развертывания, используя следующие практические рекомендации.

---

## 1. Определите, какой именно файл или папка вызывают ошибку

В зависимости от языка программирования, на котором написана ваша Lambda-функция, истинная причина сбоя может быть неочевидна из стандартного сообщения об ошибке. Разверните подходящую категорию, чтобы узнать советы по исправлению:

### Общие ошибки (для всех языков)
* **Проверка архитектуры (x86_64 vs ARM64):** Убедитесь, что архитектура, выбранная в настройках Lambda-функции, совпадает со спецификацией скомпилированных вами бинарных файлов. Если вы собирали проект на процессоре Apple Silicon (M1/M2/M3), выберите в настройках Lambda архитектуру `arm64`. Если собирали на стандартном Intel/AMD — выберите `x86_64`.
* **Чистка архива:** Перед запаковкой всегда удаляйте временные файлы операционной системы (например, файлы `.DS_Store` на macOS) и локальные конфигурации, которые могут конфликтовать со средой выполнения.

### Lambda-код на Python
* **Корректность путей импорта:** Ошибка `No module named ...` часто означает, что сторонние библиотеки были установлены в подпапку, которую Python не видит. При сборке архива пакеты из `pip install -t .` должны устанавливаться строго в корень проекта, бок о бок с вашим главным файлом (например, `lambda_function.py`).
* **Бинарные зависимости (Wheels):** Если вы используете библиотеки вроде `cryptography`, `numpy` или `pandas`, обычный `pip install` на Windows или macOS скачает бинарники под вашу домашнюю ОС. Для работы в Lambda используйте ключ `--platform manylinux2014_x86_64` и параметр `--only-binary=:all:` при скачивании пакетов через pip, либо собирайте пакет внутри Docker-контейнера `amazonlinux`.

### Lambda-код на Node.js
* **Имя обработчика (Handler):** Проверьте конфигурацию функции. Если ваш обработчик указан как `index.handler`, в корне архива обязательно должен лежать файл `index.js` (или `index.mjs`), внутри которого экспортирована функция с именем `handler`.
* **Папка node_modules:** При ручной запаковке zip-архива убедитесь, что вы выделили файлы `index.js`, `package.json` и папку `node_modules` вместе, и заархивировали их напрямую. Не архивируйте родительскую папку проекта. Если в зависимостях есть тяжелые нативные модули (например, `sharp` или `bcrypt`), их необходимо переустановить под целевую архитектуру Linux с помощью команды `npm rebuild --platform=linux --arch=x64`.

## 2. Обновите права доступа к файлам установочного пакета

Среде выполнения Lambda жизненно необходимы права на чтение файлов вашего пакета. Если права сбились (особенно после сборки на Windows), их нужно принудительно восстановить.

**Как исправить права доступа на Linux/macOS перед отправкой:**
Выполните эти команды в терминале в папке вашего проекта перед созданием zip-архива:
```bash
# Дать права 755 (чтение и выполнение) на все папки
find . -type d -exec chmod 755 {} +

# Дать права 644 (чтение) на все файлы
find . -type f -exec chmod 644 {} +
```

**Обновление пакета через AWS CLI:**
После того как вы исправили структуру или права доступа и заново упаковали файлы в архив `function.zip`, вы можете принудительно обновить код функции в облаке через терминал:
```bash
aws lambda update-function-code \
    --function-name ИМЯ_ВАШЕЙ_ФУНКЦИИ \
    --zip-file fileb://function.zip
```
