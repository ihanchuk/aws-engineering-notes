# Проблемы с нарушением прав доступа (Access Denied) в AWS Lambda

Ошибки типа `Access Denied` (Доступ запрещен) полностью блокируют выполнение задач Lambda-функции. Чаще всего это происходит, когда функция пытается обратиться к ресурсам других сервисов AWS, расположенных в **другом AWS-аккаунте**, а IAM-роль выполнения (Lambda execution role) не имеет на это соответствующих прав.

* **Пример сценария:** У вас есть Lambda-функция в Аккаунте А, которой необходимо прочитать или записать объект в бакете Amazon S3, находящемся в Аккаунте Б, но этот запрос завершается ошибкой безопасности.

---

## Симптомы проблем с Access Denied в Lambda

* **Текстовые логи:** В логах CloudWatch Logs вашей функции появляются явные ошибки вида `Access Denied`, `AuthorizationError` или `Explicit Denied` в тот момент, когда Lambda пытается выполнить API-вызов к ресурсу в Аккаунте Б.
* **Прерывание выполнения:** Вызов падает на этапе выполнения конкретной строчки кода (например, при вызове метода `s3.getObject()`), код не может продолжить работу, и функция возвращает ошибку.
