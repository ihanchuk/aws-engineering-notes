# Методы исправления проблем с Throttling в AWS Lambda

Начните исследование и устранение проблем с ограничениями (throttling), используя следующие практические рекомендации.

---

## 1. Определите, какой именно ресурс блокируется

Прежде чем вносить изменения, необходимо точно понять источник проблемы. Расширьте следующую классификацию для анализа двух возможных сценариев.

### Блокировка входящих запросов на вызов функции (Throttling on invocation requests)
* **Что делать:** Проверьте графики CloudWatch на наличие точек данных в метрике `Throttles` для вашей Lambda-функции.
* **Что это значит:** Если в метрике `Throttles` есть показатели выше нуля, это прямой сигнал о том, что на саму Lambda-функцию поступает слишком много одновременных вызовов, и она упирается в лимиты аккаунта или региона.

### Блокировка внешних API-вызовов внутри кода (Throttling on API calls made during invocation)
* **Что делать:** Изучите текстовые логи в CloudWatch Logs. Ищите там ошибки превышения лимитов (Rate exceeded / 429), при этом сама метрика Lambda `Throttles` на графиках может оставаться равной нулю.
* **Что это значит:** Это означает, что сама Lambda справляется с нагрузкой, но внешняя база данных или сторонний API, к которому обращается ваш код, не успевает переваривать запросы и блокирует вашу функцию.
* **Решение в коде:** Убедитесь, что при вызове этих API в коде используется алгоритм **экспоненциальной задержки (exponential backoff)** с добавлением случайного шума (jitter) для повторных попыток отправки запросов. Это сгладит пики нагрузки на сторонний сервис.
