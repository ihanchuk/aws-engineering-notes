# Метрики Amazon CloudWatch для AWS Step Functions

Эти метрики используются для мониторинга, отслеживания производительности и выявления ошибок в ваших стейт-машинах. Их можно разделить на три основные группы.

## 1. Метрики уровня выполнения стейт-машины (Execution)

Эти показатели относятся к жизненному циклу всей стейт-машины от момента запуска до полного завершения.

- **`ExecutionsStarted`**
  - **Описание:** Общее количество запусков (экземпляров выполнения) стейт-машины.
  - **Зачем мониторить:** Помогает отслеживать входящий трафик и общую нагрузку на систему.
- **`ExecutionsTimedOut`**
  - **Описание:** Количество запусков, которые не успели завершиться в рамках установленного лимита времени (максимум для Standard Workflows — 1 год, но обычно настраивается меньше через `TimeoutSeconds`).
  - **Зачем мониторить:** Критический показатель для алертов. Сигнализирует о том, что бизнес-логика зависла.

## 2. Метрики интеграции с сервисами (Service Integration)

Эти метрики собираются для шагов типа `Task`, которые вызывают другие сервисы AWS (например, SQS, DynamoDB, ECS) напрямую через встроенный SDK.

- **`ServiceIntegrationsStarted`**
  - **Описание:** Количество интеграций с сервисами AWS, успешно запущенных внутри шагов стейт-машины.
  - **Зачем мониторить:** Позволяет оценивать интенсивность взаимодействия с внешней инфраструктурой.
- **`ServiceIntegrationsTimedOut`**
  - **Описание:** Количество интеграций, выполнение которых было прервано из-за превышения лимита времени, настроенного в параметре `TimeoutSeconds` конкретного шага.
  - **Зачем мониторить:** Сигнализирует о проблемах или деградации производительности на стороне зависимых сервисов AWS.

## 3. Метрики вызова функций AWS Lambda (Lambda Function)

Поскольку вызов AWS Lambda — самый частый сценарий, AWS выделила мониторинг шагов, вызывающих Lambda-функции напрямую через ARN, в отдельную категорию.

- **`LambdaFunctionsStarted`**
  - **Описание:** Количество успешно инициированных вызовов ваших Lambda-функций из стейт-машины.
  - **Зачем мониторить:** Показывает реальную активность вашего серверлесс-кода.
- **`LambdaFunctionsTimedOut`**
  - **Описание:** Количество вызовов Lambda, которые превысили тайм-аут, заданный внутри самого шага стейт-машины (`TimeoutSeconds`), либо максимальный физический лимит самой функции Lambda (15 минут).
  - **Зачем мониторить:** Прямой индикатор неоптимизированного кода, «тяжелых» вычислений или бесконечных циклов.

## Сводная таблица метрик

| Метрика                           | Объект отслеживания                    | Что означает рост?                                        |
| :-------------------------------- | :------------------------------------- | :-------------------------------------------------------- |
| **`ExecutionsStarted`**           | Вся стейт-машина                       | Растет входящий поток событий или триггеров.              |
| **`ExecutionsTimedOut`**          | Вся стейт-машина                       | Стейт-машина в целом работает дольше положенного срока.   |
| **`ServiceIntegrationsStarted`**  | Интеграции с AWS (SQS, DynamoDB и др.) | Запускается много внешних задач через SDK / API.          |
| **`ServiceIntegrationsTimedOut`** | Интеграции с AWS (SQS, DynamoDB и др.) | Зависимые сервисы AWS не отвечают вовремя.                |
| **`LambdaFunctionsStarted`**      | Функции AWS Lambda                     | Активно вызывается ваш серверлесс-код.                    |
| **`LambdaFunctionsTimedOut`**     | Функции AWS Lambda                     | Код Lambda работает дольше таймаута, настроенного в шаге. |
