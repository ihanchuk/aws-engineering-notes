### NACL

NACL (Network Access Control List) — это **stateless сетевой фильтр на уровне subnet**. AWS определяет его как механизм, который позволяет разрешать или запрещать **inbound и outbound traffic** на уровне subnet.

NACL — **stateless**: если мы разрешили входящий трафик, ответный исходящий трафик автоматически не разрешается. Его нужно разрешить отдельным **outbound rule**.

#### Кратко

* работает на уровне подсети
* stateless
* задаёт правила для входящего и исходящего трафика
* фильтрует IP-трафик на основе IP-адресов, протоколов и портов (если протокол их использует)
* работает с IP-протоколами, включая TCP, UDP и ICMP
* поддерживает правила `ALLOW` и `DENY`
* правила проверяются по возрастанию `Rule Number`
* срабатывает **первое совпавшее правило**
* если ни одно правило не совпало, применяется **implicit deny**
* **default NACL** по умолчанию разрешает весь inbound и outbound traffic

> [!IMPORTANT]
> Когда VPC создаётся, у неё есть **default NACL**.
>
> Он по умолчанию содержит правила:
>
> ```text
> Inbound  → ALLOW all
> Outbound → ALLOW all
> ```
>
> Поэтому default NACL фактически разрешает весь трафик.

Каждая subnet должна быть ассоциирована с одним NACL. Если subnet явно не назначен другой NACL, AWS автоматически использует **default NACL VPC**.

Один NACL можно связать с несколькими subnet.

NACL поддерживает правила `ALLOW` и `DENY`.

У каждого правила NACL есть **Rule Number** — номер правила, который задаётся при его создании.

Это не какой-то ID, который AWS случайно выдаёт. Номер определяет **порядок проверки правил**.

|  Rule # | Type    | Protocol | Source        | Port | Action |
| ------: | ------- | -------- | ------------- | ---: | ------ |
| **100** | Inbound | TCP      | `10.0.0.0/16` |  443 | ALLOW  |
| **200** | Inbound | TCP      | `0.0.0.0/0`   |  443 | DENY   |
| **300** | Inbound | TCP      | `0.0.0.0/0`   |   80 | ALLOW  |

```text
Rule 100
   ↓
подходит?
   ├── Да → ALLOW → STOP
   └── Нет
       ↓
Rule 200
   ↓
подходит?
   ├── Да → DENY → STOP
   └── Нет
       ↓
Rule 300
   ↓
```

То есть **первое совпавшее правило побеждает**.

Правила проверяются в порядке возрастания `Rule Number`, поэтому при прочих равных правило с меньшим номером проверяется раньше.

Важно: срабатывает **только первое правило, которое совпало с пакетом**. После этого дальнейшие правила не проверяются.

### Пример для `1.2.3.4:443`

```text
100  ALLOW TCP 443 from 0.0.0.0/0
200  DENY  TCP 443 from 1.2.3.4/32
```

```text
100 → совпало → ALLOW → STOP
200 → уже не проверяется
```

> [!IMPORTANT]
> Меньший `Rule Number` имеет приоритет, если оба правила подходят.
>
> Именно поэтому в NACL порядок правил критически важен.
>
> Например, если сначала разрешить `443` для `0.0.0.0/0`, а потом попытаться запретить `443` только для `1.2.3.4/32`, запрет работать не будет: пакет уже совпадёт с правилом `100` и будет разрешён.
