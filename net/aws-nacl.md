### NACL

NACL — это stateless сетевой фильтр на уровне subnet. AWS прямо определяет его как механизм, который позволяет разрешать или запрещать inbound/outbound traffic на уровне subnet.

NACL — stateless, если мы разрешили входящий трафик, ответный исходящий трафик автоматически не разрешается. Нужно разрешить его отдельным outbound rule.

#### Кратко

- работает на уровне подсети
- стейтлесс 
- задает правила для входящего и исходящего траффика
- фильтрует IP-трафик на уровне IP-адресов, протоколов и портов.
- работает с IP и TCP/UDP траффиком
- поддерживает Allow и Deny правила
- в конце списка правил есть правило implicit deny all
- по умолчанию разрешает весь траффик

> [!IMPORTANT]
> Когда VPC создаётся, у неё есть default NACL.
> Он по умолчанию:
> ```
> Inbound  → ALLOW all
> Outbound → ALLOW all
> То есть практически весь трафик разрешён.
```

Каждая subnet должна быть ассоциирована с одним NACL. Если ты явно ничего не назначил, AWS автоматически
использует default NACL VPC. Один NACL можно связать с несколькими subnet.
NACL умеет ALLOW и DENY правила. 

У каждого правила NACL есть Rule Number — номер правила, и этот номер ты задаёшь сам при создании правила.
Это не какой-то ID, который AWS случайно выдаёт - номер нужен для определения порядка проверки правил.

|  Rule # | Type    | Protocol | Source        | Port | Action |
| ------: | ------- | -------- | ------------- | ---: | ------ |
| **100** | Inbound | TCP      | `10.0.0.0/16` |  443 | ALLOW  |
| **200** | Inbound | TCP      | `0.0.0.0/0`   |  443 | DENY   |
| **300** | Inbound | TCP      | `0.0.0.0/0`   |   80 | ALLOW  |

```
Rule 100
   ↓
подходит?
   ├── Да → ALLOW → STOP
   └── Нет
       ↓
Rule 200
   ↓
подходит?
   ├── Да → DENY → STOP
   └── Нет
       ↓
Rule 300
   ↓
```

То есть первое совпавшее правило побеждает. При прочих равных — срабатывает правило с меньшим
номером, потому что оно проверяется раньше, но толькопервое правило, которое совпало с пакетом.

### Пример для 1.2.3.4:443:
```
100  ALLOW TCP 443 from 0.0.0.0/0
200  DENY  TCP 443 from 1.2.3.4/32
```

```
100 → совпало → ALLOW → STOP
200 → уже не проверяется
```
> [!IMPORTANT]
> Меньший номер имеет приоритет, если оба правила подходят.
Именно поэтому в NACL порядок правил — критически важен.
