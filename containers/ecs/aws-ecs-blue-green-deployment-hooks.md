# Blue/Green Deployment Hooks

`Lifecycle Hooks` — это специальные точки на временной шкале деплоя, в которых процесс замирает и ждет выполнения вашего кастомного кода (обычно это `AWS Lambda` функция).
Они используются исключительно при `Blue/Green` развертывании (через AWS CodeDeploy или native ECS Blue/Green). При обычном Rolling Update хуков нет.

Главная цель хуков — проверить новую версию (Green) в реальных условиях ДО того, как на нее пойдет боевой трафик, или сразу после переключения, чтобы вовремя заметить 
проблему и автоматически нажать кнопку «Откат» (Rollback).

### Хуки

```text
[Старт деплоя] 
       │
       ▼
1. BeforeInstall ──► (Редко: подготовка ресурсов)
       │
       ▼
   [ECS запускает таски Green]
       │
       ▼
2. AfterInstall  ──► (Важно! Тестируем Green на тестовом порту)
       │
       ▼
   [Трафик переключается на Green]
       │
       ▼
3. AfterAllowTraffic ──► (Проверяем Green под реальной нагрузкой)
       │
       ▼
   [Время ожидания / Bake Time]
       │
       ▼
4. BeforeAllowTraffic ──► (Редко: финальная зачистка)
```

## CodeDeploy Lifecycle Hooks

### 1. `AfterInstall` ⭐

> **Самый популярный вариант**

**Когда вызывается:**  
Когда **ECS** уже успешно запустил новые контейнеры (**Green-версию**) и они прошли базовый Health Check балансировщика, но основные пользователи ещё не видят новую версию.

**Зачем нужен:**  
В этот момент новая версия доступна для тестирования, например через специальный test listener/port (`:8080`).

Lambda-функция на этом hook может:

- запустить integration tests;
- проверить endpoint `/health`;
- проверить подключение к базе данных;
- выполнить несколько тестовых запросов;
- проверить основную бизнес-логику.

**Результат:**

- `Success` → deployment продолжается.
- `Failure` → deployment останавливается, Green tasks удаляются, а production traffic остаётся на Blue-версии.

---

### 2. `AfterAllowTraffic`

**Когда вызывается:**  
После того как **ALB** переключил production traffic на новые контейнеры.

При Canary/Linear deployment это может быть только первая часть traffic, а не обязательно 100%.

**Зачем нужен:**  
Проверить, как новая версия ведёт себя уже после получения реального production traffic.

Lambda-функция может:

- проанализировать метрики **CloudWatch**;
- проверить всплеск `5xx` ошибок;
- проверить latency;
- проверить application/business metrics;
- выполнить дополнительные smoke tests.

**Результат:**  
Если за заданный период, например 5 минут, Lambda обнаруживает аномалии, deployment можно остановить и выполнить rollback к **Blue-версии**.

---

### Lifecycle

```text
Blue v1
   │
   ▼
Deploy Green v2
   │
   ▼
AfterInstall
   │
   ├── Failure → Stop deployment
   │
   ▼
Allow Traffic
   │
   ▼
AfterAllowTraffic
   │
   ├── Failure → Rollback → Blue v1
   │
   ▼
Green v2
