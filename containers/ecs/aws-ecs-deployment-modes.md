# ECS deployment modes

В Amazon Elastic Container Service (Amazon ECS) доступны две основные стратегии развертывания: `Rolling Update` (замена строго инстанса новым обновление) и Blue/Green (одновременно существует старая и новая версия). 
Главное отличие между ними заключается в том, как именно распределяются ресурсы в процессе обновления и каким образом переключается пользовательский трафик


### Roling Update ###

При этой стратегии ECS постепенно заменяет старые контейнеры (таски) на новые. Поведение ECS регулируется двумя ключевыми параметрами:
- __Minimum healthy percent__ — минимальный процент тасок, который должен оставаться в рабочем состоянии (RUNNING). Если у вас настроено 4 таски, а лимит равен 100%, ECS не убьет ни одну старую таску, пока не запустит новые.
- __Maximum percent___ — максимальный лимит тасок, который разрешено запустить во время деплоя (например, 200% позволит временно удвоить количество тасок для быстрого обновления).

Когда использовать: 
- Для стандартных микросервисов, не требующих сложного тестирования перед релизом.
- При жестких ограничениях бюджета на инфраструктуру

### Blue/Green ### 

ECS создает абсолютно новый набор тасок (Green) рядом с текущим (Blue). Новая версия запускается в изолированной целевой группе (Target Group). 
Вы можете прогнать тесты на тестовом порту (тестовом Listener) и, если все в порядке, переключить основной продуктовый трафик на Green. 
Старая версия (Blue) уничтожается только после истечения времени ожидания (Bake time).

Встроенные подстратегии трафика:
- __All-at-once__: Мгновенный перенос 100% трафика на новую версию.
- __Canary__: Сначала на Green переводится малая часть трафика (например, 10%), а через заданное время — оставшиеся 90%.
- __Linear__: Трафик переносится равными частями по графику (например, по 10% каждые пару минут).

Когда использовать:
- ___Несовместимые миграции БД__: Когда старый и новый код не могут работать с базой данных одновременно.
- __Долгие соединения__ (WebSockets/gRPC): Для минимизации разрывов соединений и контролируемого переключения.
- __Критически важные сервисы__: Где требуется мгновенный откат в случае обнаружения ошибок
