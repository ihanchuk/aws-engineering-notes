# ECS Networking Modes

* **Host Mode** — наиболее базовый режим сетевого взаимодействия, при котором контейнер использует сетевой стек хоста (сетевые интерфейсы, маршрутизацию, таблицы соединений и т. д.). Контейнер разделяет network namespace с базовым EC2-инстансом и использует его IP-адрес.

  В результате контейнеры имеют меньшую сетевую изоляцию, а опубликованные порты контейнера напрямую соответствуют портам хоста. Поэтому два контейнера на одном EC2-инстансе не могут одновременно использовать один и тот же host port.

  Контейнер сохраняет процессную изоляцию, предоставляемую Linux namespaces и cgroups, но не имеет отдельного сетевого namespace и поэтому использует сетевой стек хоста.

  * 👍 **Плюсы:**

    * **Максимально быстро**. Поскольку виртуальный сетевой уровень (например, docker0 bridge) исключается, сетевые пакеты идут напрямую к интерфейсу EC2. Это обеспечивает минимальную задержку (latency) и высокую пропускную способность.
    * **Простота**. Нет необходимости настраивать сложные правила маршрутизации портов или выделять отдельные сетевые интерфейсы (ENI) для каждой задачи.

  * 👎 **Недостатки:**

    * **Конфликты портов**: Вы не можете запустить более одной копии (задачи) приложения на одном EC2-хосте, если они используют один и тот же порт.
    * **Отсутствие динамического маппинга**: В отличие от режима bridge, здесь нельзя перенаправить контейнерный порт `80` на случайный порт хоста, например `8080`.
    * **Безопасность**: Контейнеры имеют доступ к локальным сервисам хоста (`localhost`), что увеличивает уязвимость.
    * **Ограничение платформы**: Этот режим поддерживается только для инфраструктуры EC2 и недоступен для AWS Fargate.

* **Bridge Mode** — в сетевом режиме Bridge Mode (`bridge`) используется внутренняя виртуальная сеть Docker, встроенная в операционную систему хоста (инстанса Amazon EC2). Этот режим позволяет изолировать сетевое пространство контейнеров друг от друга и от самого хоста, управляя трафиком через встроенный мост (`docker0`).

  В режиме bridge контейнеры получают внутренние IP-адреса из закрытого диапазона Docker. Чтобы сделать приложение доступным снаружи, ECS связывает порт контейнера с портом хоста (маппинг портов).

  **Два режима маппинга:**

  * **Статический маппинг** — жёстко связывает порт контейнера и порт хоста (например, `80` контейнера → `80` хоста). Это создаёт ту же проблему с конфликтом портов, что и в Host Mode.

  * **Динамический маппинг** — мы указываем `containerPort` (например, `8080`), а `hostPort` оставляем равным `0`. При запуске задачи ECS автоматически выделяет свободный порт хоста.

  * 👍 **Плюсы:**

    * **Динамические порты**: Главный плюс режима. Вы можете запустить несколько копий (задач) одного и того же приложения на одном EC2-инстансе. Каждая копия получит свой уникальный порт на хосте.
    * **Интеграция с ALB**: Динамический маппинг хорошо работает с Application Load Balancer (ALB). ECS сообщает балансировщику, какой порт получила конкретная задача, и ALB направляет трафик туда.
    * **Изоляция**: Контейнеры имеют отдельные network namespaces и изолированы от сетевого пространства хоста.
