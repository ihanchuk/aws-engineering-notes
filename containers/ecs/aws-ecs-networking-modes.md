# ECS Networking Modes

- **Host Mode** — наиболее базовый режим сетевого взаимодействия, при котором контейнер использует сетевой стек хоста (сетевые интерфейсы, маршрутизацию, таблицы соединений и т. д.). Контейнер разделяет network namespace с базовым EC2-инстансом и использует его IP-адрес.

  В результате контейнеры имеют меньшую сетевую изоляцию, а опубликованные порты контейнера напрямую соответствуют портам хоста. Поэтому два контейнера на одном EC2-инстансе не могут одновременно использовать один и тот же host port.

   Контейнер сохраняет процессную изоляцию, предоставляемую Linux namespaces и cgroups, но не имеет отдельного сетевого namespace и поэтому использует сетевой стек хоста.
    - 👍 Плюсы:
      - __Максимально быстро__.  Поскольку виртуальный сетевой уровень (например, docker0 bridge) исключается, сетевые пакеты идут напрямую к интерфейсу EC2. Это обеспечивает минимальную задержку (latency) и высокую пропускную способность.
      - __Простота__ Нет необходимости настраивать сложные правила маршрутизации портов или выделять отдельные сетевые интерфейсы (ENI) для каждой задачи.
    - 👎 Недостатки:
      - __Конфликты портов__: Вы не можете запустить более одной копии (задачи) приложения на одном EC2-хосте, если они используют один и тот же порт.
      - __Отсутствие динамического маппинга__: В отличие от режима bridge, здесь нельзя перенаправить контейнерный порт 80 на случайный порт хоста например 8080
      - __Безопасность__: Контейнеры имеют доступ к локальным сервисам хоста (localhost), что увеличивает уязвимость.
      - __Ограничение платформы__: Этот режим поддерживается только для инфраструктуры EC2 и недоступен для AWS Fargate.
